01. Authentication & JWT Session Hook

The Loan Officer accesses the platform using institutional credentials. The server verifies passwords via bcrypt (12 salt rounds) and issues a cryptographically signed jsonwebtoken (JWT), which is stored in client memory. Auto-logout is triggered on 401 token expiry.

Logged Event: LOGIN_SUCCESS • Parameters: email, timestamp, client IP

02. Borrower Profile Registry

The officer fills in the borrower parameters: FICO score, Gross Monthly Income, Monthly Debt, and Loan Request. The application runs client-side Joi logic validating ages (must be ≥ 18) and FICO credit ranges (300-850) before sending requests.

Logged Event: CREATE_APPLICANT • Parameters: Applicant ID, Loan Officer ID

03. Parallel Engine Evaluation

Clicking "⚙️ RUN RISKS" issues a POST call, spawning three parallel tasks: 1. Risk Calculation: Computes Debt-to-Income (DTI), Loan-to-Income (LTI) ratios and composite risk thresholds. 2. KYC/Fraud checks: Scans database for SSN velocity and outliers. 3. Gemini AI API: Dispatches structured profile data to the Gemini generative framework.

Logged Event: ASSESS_APPLICANT • Parameters: risk score, fraud flags, decision

04. Auditor Review & Compliance Sign-off

The Officer reviews details, FICO gauges, and the Gemini AI summary paragraphs. Once checks are verified, they click **"Sign-off Compliance Registry"**. A rotating metallic digital seal stamp animates into view, locking the audit block with timestamp and SHA-256 integrity tags.

Logged Event: VERIFY_COMPLIANCE • Parameters: audit hash, auditor credentials

05. PDF Report Generation & Streaming

The client clicks "📄 Download Report". The backend authenticates permissions, fetches fresh SQL results, and uses PDFKit to stream a binary PDF vector stream directly to the client response (preventing local disk writes to keep servers clean).

Logged Event: DOWNLOAD_REPORT • Parameters: Applicant ID, Officer ID

Generative Synthesis

Google Gemini AI Reports

FinGenius leverages the @google/genai SDK running the Gemini 2.5 Flash model to automatically summarize and analyze borrower credit parameters.

  • 1
    Strict JSON Structured Output: The server requests a strictly validated JSON structure containing four narrative fields to ensure consistent parser consumption.
  • 2
    Robust Error Tolerance & Mock Fallbacks: If the Google API threshold rate limits or is missing keys, the backend automatically generates a context-aware mock assessment locally, avoiding crashes.
  • 3
    Database Narrative Persistence: The four paragraphs are written directly to the database as risk record metrics, making them accessible instantly upon later inspection.

System Security Hardening

FinGenius complies with standard financial sector guidelines through comprehensive hardware and software hardening layers:

  • ✓
    Helmet HTTP Response Hardening: Configures Content Security Policy (CSP), HTTP Strict Transport Security (HSTS), and frames boundaries to block clickjacking and scripting.
  • ✓
    Double-Tier Express Rate Limiters: Protects endpoints with a strict 100 requests per 15 minutes restriction on authentication routes and a 500 requests general limit per IP.
  • ✓
    Append-Only Audit Ledger: The MySQL schema blocks update and delete calls on the audit_logs table, creating an immutable compliance trail.
  • ✓
    Winston Daily Rotating Logs: Logs are systematically written to persistent files (logs/combined.log) with structured JSON layouts.
